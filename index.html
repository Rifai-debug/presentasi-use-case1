Relasi & Penjelasan

  • Association Admin dan Mahasiswa berinteraksi langsung dengan sistem melalui fitur login, jadwal, dan pengajuan.
  • Include Use case Login mencakup validasi data user. Tanpa validasi, proses login tidak bisa berlangsung.
  • Extend Use case Pengajuan dapat diperluas ketika user menambahkan dokumen atau revisi data sebelum disetujui.
  • Generalization Admin dan Mahasiswa merupakan bentuk khusus dari pengguna umum (User), sehingga memiliki perilaku dasar yang sama.

Poin Penting

  • Use case menggambarkan kebutuhan fungsional sistem.
  • Aktor mewakili pihak yang berinteraksi dengan sistem.
  • Relasi menjelaskan hubungan antar aktor dan use case.
  • Diagram ini memudahkan pemahaman alur kerja aplikasi.

Penjelasan Singkat

  • Admin mengelola data akademik dan jadwal.
  • Mahasiswa mengakses jadwal dan mengajukan kebutuhan.
  • Login merupakan prerequisite utama untuk semua interaksi.
  • Penilaian adalah proses hasil akhir setelah aktivitas utama selesai.
